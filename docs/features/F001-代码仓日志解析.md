# F001: 代码仓日志解析模块

> Status: spec | Owner: 奉孝 (@ragdoll-pa82, GLM-5.2) | Reviewer: TBD（跨家族）

## Why

代码飞轮项目的四个模块（解析/离线分析/在线扫描/改进）依赖同一份"代码仓日志埋点图谱"作为底座。本 feature 构建 M1：从代码仓中识别所有日志埋点，抽取确定性上下文 + LLM 推断打印原因，经用户筛选后入库为 M2/M3/M4 提供查询面。

## What

### 一、模块定位

M1 不自建 AST / 不自建 call graph——**用 gitnexus 做 graph backend，M1 只做日志埋点识别 + 字段抽取 + LLM 推断 + 候选筛选**。

### 二、四子单元架构

```
┌─────────────────────────────────────────────────┐
│ Unit A: Repo Registrar                           │
│ - 输入: repo_url | local_path                    │
│ - 动作: gitnexus analyze --name <alias> <path>   │
│ - 输出: repo_id + gitnexus_repo_alias            │
│ - 安全: URL 白名单(https only) + 本地路径沙箱    │
└─────────────────────────────────────────────────┘
                       ↓ repo_id
┌─────────────────────────────────────────────────┐
│ Unit B: Log Point Finder (M1 核心)               │
│ - 输入: repo_id                                  │
│ - 动作:                                          │
│   1. cypher 查所有 CALLS 到 log/print/error 等命名│
│   2. 规则匹配各语言日志调用 pattern              │
│   3. tree-sitter 读调用点行号 + 函数签名         │
│   4. gitnexus context() 取调用链上下文           │
│ - 输出: List[LogPoint]（候选池，未持久化）        │
│ - 去重键: (repo_id, file_path, line_start)       │
└─────────────────────────────────────────────────┘
                       ↓ List[LogPoint]
┌─────────────────────────────────────────────────┐
│ Unit C: LLM Hypothesis Generator                 │
│ - 输入: List[LogPoint]（候选）                   │
│ - 动作: 批量调 LLM 生成"打印原因"假设           │
│ - 输出: LogPoint.llm_hypothesis 填充             │
│ - 节流: 批量 + Redis 缓存(同 log_template 复用)   │
└─────────────────────────────────────────────────┘
                       ↓ List[LogPoint]（带 LLM 假设）
┌─────────────────────────────────────────────────┐
│ Unit D: Candidate Staging + Ingestion Gate       │
│ - 输入: List[LogPoint]（带 LLM 假设）            │
│ - 动作:                                          │
│   1. 写候选池(candidate_staging 表，不进主表)    │
│   2. 按 occurrence_count 排序                    │
│   3. 标记 Top N(N 配置项) 高频候选              │
│   4. 等用户在 UI 筛选 → confirm → 入主表         │
│ - 输出: 候选池状态                               │
└─────────────────────────────────────────────────┘
```

### 三、LogPoint 数据契约

```python
@dataclass
class LogPoint:
    id: str                              # UUID
    repo_id: str
    file_path: str
    function_signature: str              # 来自 gitnexus Function 节点
    line_start: int
    line_end: int
    language: Literal["c", "python"]
    log_level: str                       # INFO/WARN/ERROR/DEBUG/UNKNOWN
    log_message_template: str            # "User {uid} logged in"
    log_message_variables: list[str]     # ["uid"]
    framework_hint: str                 # "logging" | "log4c" | "printf" | "print"

    # --- 确定性上下文（来自 gitnexus）---
    enclosing_class: str | None
    call_chain_to_entry: list[str]       # gitnexus context() 取
    enclosing_community: str | None     # gitnexus community label

    # --- 历史案例推荐（确定性）---
    evidence_refs: list[CaseRef]         # 同 community + 同 log_template 的过往案例

    # --- LLM 推断（每条候选都跑）---
    llm_hypothesis: LLMHypothesis | None # 候选阶段可空，confirmed 入库后必填

    # --- 频次 + 入库状态 ---
    occurrence_count: int                # 候选池中累计频次
    ingestion_status: Literal["candidate", "confirmed", "ingested"]
    first_seen_at: datetime
    last_seen_at: datetime


@dataclass
class LLMHypothesis:
    summary: str                         # 一句话假设
    possible_causes: list[str]           # 可能触发原因列表
    suggested_check: str | None          # 建议人工核查点（可选）
    model_name: str                      # 用了哪个模型，便于追溯
    generated_at: datetime


@dataclass
class CaseRef:
    case_id: str
    repo_id: str
    file_path: str
    function_signature: str
    log_template: str
    resolved_at: datetime
```

### 四、日志调用识别规则（Unit B）

| 语言 | 框架 | 识别模式 |
|------|------|---------|
| Python | logging | `logging.info/warn/error/debug/warning/critical/exception(` |
| Python | loguru | `logger.<level>(` |
| Python | 裸 print | `print(`（仅当位于 try/except 包裹内或函数名含 log/error 时纳入；否则过滤；`log_level` 统一记为 UNKNOWN） |
| C | stdio | `printf(`/`fprintf(stdout/stderr,` |
| C | syslog | `syslog(` |
| C | 自定义 | 同 repo 内命名匹配 `^.*_(log|error|debug|trace).*$` 的函数调用 |

**过滤规则**：注释行、字符串字面量内的"log"关键字不识别；只识别真实函数调用。

### 五、对外 API 契约

```python
class RepoLogGraphService:
    def ingest_repo(self, source: RepoSource, ingester: User) -> RepoId:
        """clone+gitnexus analyze+候选池构建一步到位"""

    def list_candidates(
        self, repo_id: RepoId, filter: CandidateFilter
    ) -> list[LogPoint]:
        """用户筛选 UI 调用：列高频候选（按 occurrence_count 倒序，Top N）"""

    def confirm_ingestion(
        self, repo_id: RepoId, log_point_ids: list[str], confirmer: User
    ) -> None:
        """用户勾选后调，候选 → 主表（P0 持久化铁律：用户 opt-in 才入库）"""

    def query_log_points(
        self, repo_id: RepoId, filters: LogPointFilter
    ) -> list[LogPoint]:
        """M2 调用：查主表（仅 ingested 状态）"""

    def get_call_context(
        self, repo_id: RepoId, function_signature: str
    ) -> CallContext:
        """M4 调用：通过 gitnexus context() 取调用链 + 同 community 案例"""
```

**契约文件位置**：`packages/contracts/`（单独子包，M2/M3/M4 import 这些 dataclass 而非依赖 M1 内部实现）

## Acceptance Criteria

- [ ] AC-1: Unit A 能接收 GitHub URL 或本地路径，调 `gitnexus analyze` 完成建图，返回 `repo_id`
- [ ] AC-2: Unit A 拒绝 `..` 越权路径与非 https URL（含测试用例验证拒绝）
- [ ] AC-3: Unit B 对 Python logging / Python print / C printf 三种 pattern 各有 fixture 测试，能识别出 LogPoint 并正确填充确定性字段
- [ ] AC-4: Unit B 输出去重（同 `(repo_id, file_path, line_start)` 只一条）
- [ ] AC-5: Unit C 批量调 LLM 生成假设；同 `log_template` 在 Redis 缓存命中时不重复调
- [ ] AC-6: Unit C 失败时 LogPoint 仍入库（`llm_hypothesis=None`），不阻塞流水线
- [ ] AC-7: Unit D 候选池表与主表分离，`ingestion_status` 状态机正确：`candidate → confirmed → ingested`
- [ ] AC-8: Unit D 按配置项 `top_n_candidates`（默认 50）标记高频候选
- [ ] AC-9: `confirm_ingestion` 仅在用户显式勾选后调用才入主表；无 confirm 路径直接写入主表 = P0 bug
- [ ] AC-10: LLM key 通过配置文件注入（`config.local.yaml` 或 env var），代码中无硬编码 key
- [ ] AC-11: `query_log_points` 只返回 `ingested` 状态的 LogPoint
- [ ] AC-12: 跨家族 review 通过（家规铁律：no self-review）

## Risk

| 风险 | 等级 | 缓解 |
|------|------|------|
| gitnexus CALLS 边命名匹配不准（如 `format_error` 被误识别为日志调用） | 🟡 中 | Unit B 加规则白名单 + tree-sitter 二次确认 |
| LLM 调用成本（每条候选都跑） | 🟡 中 | Redis 缓存 + 批量 + 同 log_template 复用 |
| 候选池表无限增长 | 🟢 低 | occurrence_count=0 超过 TTL(默认 30 天) 自动清理 |
| LLM 输出幻觉（生成的"可能原因"不准确） | 🟡 中 | `llm_hypothesis` 标注为"参考假设"，不作为 M4 自动改代码依据 |
| 跨 thread 协作时平行自己不知道这条 spec | 🟡 中 | spec 文件 commit push 后记忆系统会索引 |
| gitnexus 仓跨平台路径分隔符 | 🟢 低 | 测试覆盖 Windows + Linux |
