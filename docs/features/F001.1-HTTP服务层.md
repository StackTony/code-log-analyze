# F001.1: HTTP 服务层

> Status: spec (v1 — 云长+文若架构 review 整合修订) | Owner: 奉孝 (@ragdoll-pa82, GLM-5.2, Siamese) | Reviewer: @云长（跨家族）

## Why

F001 落地了 M1 `RepoLogGraphService` 6 个 API（pure Python class，77 测试全绿已 merge 到 master），但只能在进程内调用。要让铲屎官/前端/其他业务团队真正用起来 6 个 API，必须包 HTTP 层。本 feature 给 M1 service 包 FastAPI HTTP wrapper，启动 API server :3004 + metrics server :9100。

**前置依赖**：F001 已 merge（commit 87e2db9, tag f001-v1）。本 feature 不修改 M1 service 层任何代码，只在 `packages/api/` 新增 HTTP wrapper 子包。

## What

### 一、模块定位

F001.1 是 M1 的 HTTP 包装层，**只做 wrapper 不改 service**。6 个 endpoint 一一映射 M1 6 个 API 方法，加 `/health`/`/ready`/`/docs`/`/metrics` 4 个运维 endpoint。

**设计原则**：
- HTTP 层只做协议转换 + 错误格式统一，业务逻辑全在 M1 service
- Pydantic v2 BaseModel 作为 API schema，与 M1 dataclass 解耦（独立演化）
- metrics 9100 独立进程（`multiprocessing.Process`，避免 uvicorn --reload 重启 metrics）
- F001.1 不做认证（dev-only，启动 console 警告），F001.2/M3 加 RBAC
- 家规铁律：API 3004 / metrics 9100 / frontend 3003 分离

| Method | Path | Body / Query | Returns | service 方法 | tag |

| POST | `/confirm/{repo_id}` | `ConfirmRequest` | 204 No Content | `confirm_ingestion` | ingestion |
| POST | `/revoke/{repo_id}` | `RevokeRequest` | 204 No Content | `revoke_ingestion` | ingestion |
| GET | `/log-points/{repo_id}` | `?file_path&function_signature&log_level` | `list[LogPointAPI]` 200 | `query_log_points` | query |
| POST | `/call-context/{repo_id}` | `CallContextRequest` | `CallContextAPI` 200 | `get_call_context` | query |
| GET | `/health` | — | `{status: "ok"}` 200 | — | ops |
| GET | `/ready` | — | `{status: "ready"|"not_ready", reason?}` 200 | — | ops |

| GET | `/docs` | — | Swagger UI | — | (FastAPI 自带) |
| GET | `/openapi.json` | — | OpenAPI 3.1 spec | — | (FastAPI 自带) |

**云长 OQ-1 修订**：`/call-context/{repo_id}` 改为 POST + body（避免 URL encode 复杂签名）。

**云长 I-2 修订**：补 `/ready` endpoint 区分 liveness/readiness。

**状态码语义**：
- 200 OK：GET 成功
- 201 Created：POST `/ingest` 成功（产生新资源 repo_id）
- 204 No Content：POST `/confirm`/`/revoke` 成功（无响应体）
- 400 INVALID_PATH：UnsafePathError
- 409 INGEST_LOCK_RUNNING：repo 正在解析中
- 422 VALIDATION_ERROR：Pydantic 验证失败
- 422 REPO_NOT_FOUND：repo_id 不存在
- 500 INTERNAL_ERROR：未捕获异常
- 503 NOT_READY：`/ready` 检查失败（DB 不可达）

### 四、数据流（ingest 全链路）

```
1. POST /ingest {local_path, ingester}
2. FastAPI Pydantic strict 验证 → IngestRequest
3. deps.get_service() 注入 RepoLogGraphService（per-request session）
4. service.ingest_repo(source, ingester) → repo_id
   - 若 lock 表已有 running 状态 → 返回 409 INGEST_LOCK_RUNNING
   - 若 local_path 不存在/越权 → 返回 400 INVALID_PATH
5. mappers.log_point_to_response 转换（如需返回 LogPoint）
6. IngestResponse pydantic 序列化 → JSON
7. 同时 metrics: m1_ingest_repo_duration_seconds.observe(...)
8. 返回 201 + {repo_id}
```

**异常映射**（云长 C-1 + I-1 修订）：

```python
# packages/api/error_handlers.py
@app.exception_handler(UnsafePathError)
async def handle_unsafe_path(exc):
    return JSONResponse(400, {"code": "INVALID_PATH", "message": str(exc), "details": {}})

@app.exception_handler(UnsafeUrlError)

# 404/409/500 通过 raise HTTPException(status_code=..., detail={code, message, details}) 实现
```

**RepoIngestLock running 处理（云长 C-1 修订）**：

M1 `RepoRegistrar.ingest()` 遇 running 状态时**静默 return existing repo_id**（不抛异常）。HTTP 层需要在调 service 前先查 lock 表状态：

```python
# packages/api/routes/ingest.py
from packages.m1.storage.models import RepoIngestLockModel
from sqlalchemy import select

@router.post("/ingest", response_model=IngestResponse, status_code=201)
def ingest(req: IngestRequest, service: RepoLogGraphService = Depends(get_service)):
    # 先查 lock 表 running 状态（云长 C-1 修订）
    existing = service._session.scalar(
        select(RepoIngestLockModel)
        .where(RepoIngestLockModel.repo_id == _compute_repo_id(req))
        .where(RepoIngestLockModel.status == "running")
    )
    if existing:
        raise HTTPException(409, detail={
            "code": "INGEST_LOCK_RUNNING",
            "message": f"repo {existing.repo_id} is being ingested",
            "details": {"repo_id": existing.repo_id, "status": "running"}
        })
    repo_id = service.ingest_repo(...)
    return IngestResponse(repo_id=repo_id)
```

### 六、metrics 9100 独立进程（云长 C-2 + 文若 W-1 修订）

```python
# packages/api/app.py
import multiprocessing
import logging
from contextlib import asynccontextmanager
from prometheus_client import start_http_server

@asynccontextmanager
async def lifespan(app: FastAPI):
    logger = logging.getLogger(__name__)

    # metrics server 独立进程（文若 W-1 修订：避免 uvicorn --reload 重启 metrics）
    metrics_process = None
    try:
        metrics_process = multiprocessing.Process(
            target=start_http_server, args=(9100,), daemon=True
        )
        metrics_process.start()
        logger.info("Metrics server started on port 9100 (pid={})", metrics_process.pid)
    except Exception as e:
        # 云长 C-2 修订：graceful degradation，metrics 启动失败不阻断 API
        logger.warning(f"Metrics server failed to start: {e}. Continuing without metrics.")

    # 启动 console 警告（AC-7）
    logger.warning("⚠️  未启用认证，dev-only 模式 — 禁止暴露公网")

    yield

    # cleanup
    if metrics_process and metrics_process.is_alive():
        metrics_process.terminate()
        metrics_process.join(timeout=2)
```

## Risk

| 风险 | 等级 | 缓解 |
|------|------|------|
| metrics 9100 端口冲突（dev 环境多实例） | 🟡 中 | AC-11 graceful degradation + test fixture 用 9101 避免冲突 |
| uvicorn --reload 重启 metrics server 丢累积值 | 🟡 中 | AC-10 用 multiprocessing.Process 独立进程，uvicorn 重启不影响 |
| Pydantic strict 模式过严，合法请求被拒 | 🟢 低 | strict 只对类型严格（int≠str），extra=forbid 拒绝拼写错误字段名 |

| Windows uvloop 不可用 | 🟢 低 | uvicorn 自动 fallback asyncio，spec 显式声明 |
