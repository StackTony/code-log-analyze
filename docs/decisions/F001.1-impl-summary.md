# F001.1 HTTP 服务层 — 实现功能提炼

> Author: 奉孝 (@ragdoll-pa82, GLM-5.2, Siamese)
> Status: 实施完成，待 merge-gate review

## 实现了哪些功能

### 一、HTTP 服务层（packages/api/）

#### 1. FastAPI app + lifespan（packages/api/app.py）

- **FastAPI 实例** + **lifespan async context manager**
- **metrics server 独立进程**（multiprocessing.Process，避免 uvicorn --reload 丢累积值）
- **graceful degradation**：metrics 启动失败不阻断 API
- **CORS 中间件**（cors_origins 配置化，默认 localhost:3003 — F003 前端）
- **启动 console 警告**：未启用认证，dev-only 模式

#### 2. 9 个 endpoint

| Method | Path | 功能 | tag |
|--------|------|------|-----|
| POST | /ingest | ingest 代码仓 → 返回 repo_id | ingestion |
| GET | /candidates/{repo_id} | 列候选池 LogPoint | query |
| POST | /confirm/{repo_id} | 候选 → 主表（用户勾选） | ingestion |
| POST | /revoke/{repo_id} | 主表 → 候选（状态回退，MF-2 不删） | ingestion |
| GET | /log-points/{repo_id} | 查主表 confirmed/ingested | query |
| POST | /call-context/{repo_id} | 取调用上下文 | query |
| GET | /health | liveness probe | ops |
| GET | /ready | readiness probe（查 DB 连接） | ops |
| GET | /metrics | Prometheus exposition（内嵌兜底） | ops |
| GET | /docs | Swagger UI | (自带) |
| GET | /openapi.json | OpenAPI 3.1 spec | (自带) |

#### 3. Pydantic v2 BaseModel schemas（packages/api/schemas/）

- **strict=True** + **extra="forbid"** + **from_attributes=True**
- 与 M1 dataclass 解耦（API schema 独立演化）
- 5 个 BaseModel：ErrorResponse / IngestRequest+Response / LogPointAPI+LLMHypothesisAPI / CallContextAPI+CaseRefAPI / ConfirmRequest+RevokeRequest+CallContextRequest
- 24 字段对齐 LogPoint dataclass（AC-6 + MF-4）

#### 4. Mappers（packages/api/mappers/）

- **log_point_to_response**：LogPoint dataclass → LogPointAPI Pydantic
- **call_context_to_response**：CallContext dataclass → CallContextAPI
- 集中转换逻辑（M2/M3/M4 复用，文若 W-4）

#### 5. 错误处理（packages/api/error_handlers.py）

- **统一格式** `{code, message, details}`
- **5 个异常映射**：
  - UnsafePathError → 400 M1_INVALID_PATH
  - UnsafeUrlError → 400 M1_INVALID_URL
  - RequestValidationError → 422 GENERIC_VALIDATION_ERROR
  - HTTPException → 409/422/500（detail 含 code/message/details 透传）
  - Exception → 500 GENERIC_INTERNAL_ERROR
- **错误码命名空间**（文若 W-5）：M1_* / M2_* / M3_* / M4_* / GENERIC_*

#### 6. 依赖注入（packages/api/deps.py）

- **全局 engine + SessionLocal**（每个 uvicorn worker 独立）
- **get_session() Depends** — per-request session（generator yield + close）
- **get_service() Depends** — 构造 RepoLogGraphService（mock 友好，复用 M1 构造逻辑）
- **云长 C-1 修订**：ingest route 先查 RepoIngestLockModel running 状态，避免 M1 service 静默 return repo_id

### 二、配置扩展（packages/m1/config_loader.py）

- 新增 `ApiConfig` dataclass：host/port/enable_auth/cors_origins
- 默认值：host=127.0.0.1, port=3004（家规铁律）, enable_auth=False, cors_origins=("http://localhost:3003",)
- 环境变量覆盖：CODEFLY_API_HOST / CODEFLY_API_PORT / CODEFLY_API_ENABLE_AUTH / CODEFLY_API_CORS_ORIGINS
- config.example.yaml 补 api 段

### 三、测试体系（tests/api/）

- 62 个 F001.1 测试覆盖 14 AC（总计 139 passed, 1 skipped）
- **分层**：
  - tests/api/ — HTTP 层（TestClient）
  - tests/e2e/ — service 层（M1 既有）
  - tests/unit_*/ — unit 层（M1 既有）
- **metrics fixture** 用 9101 端口避免与 app lifespan 9100 冲突
- **schema validation** 验证 24 字段对齐 + strict mode + from_attributes
- **AC coverage** 自检 — 14 AC 全映射测试

### 四、运维 endpoint

- `/health` — liveness probe（进程存活）
- `/ready` — readiness probe（DB 连接检查）
- `/metrics` — Prometheus exposition（FastAPI 内嵌兜底 + 9100 独立进程主路）
- `/docs` — Swagger UI（自动按 tag 分组：ingestion / query / ops）
- `/openapi.json` — OpenAPI 3.1 spec

## 启动方式

```bash
# 安装依赖
pip install -e ".[api,dev]"

# 配置环境变量
export CODEFLY_LLM_API_KEY=sk-...
export CODEFLY_PG_DSN=postgresql://localhost/codefly

# 启动（dev-only，自动起 metrics 9100 + API 3004）
python -m packages.api
# 或
uvicorn packages.api.app:app --port 3004 --reload

# 浏览器访问 API 文档
open http://localhost:3004/docs
```

## Scope 边界（明确不做）

- ❌ 认证 / RBAC（留 F001.2 或 M3）
- ❌ CORS 写死 localhost:3003（F003 前端开发时再开放）
- ❌ HTTPS / TLS（dev-only）
- ❌ rate limiting
- ❌ API versioning（`/v1/...` 路径前缀留生产部署时加）
- ❌ 持久化实例（继续用 :memory: 或外部 PostgreSQL，M1 配置已有）
- ❌ 修改 M1 service 层任何代码（铁律 — F001.1 是纯 wrapper）

## 后续扩展点（M2/M3/M4 复用）

- **schemas/mappers 复用**：M2/M3/M4 可直接 import `packages/api/schemas/log_point.py` 和 `mappers/log_point.py`
- **错误码命名空间**：M2_* / M3_* / M4_* 预留
- **依赖注入模式**：`get_service` Depends 模式可扩展到 M2/M3/M4 service
- **tag 分组模式**：M2/M3/M4 各自一组 tag（`m2_analysis` / `m3_scan` / `m4_improve`）
